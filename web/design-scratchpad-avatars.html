Verso — avatars and the ejection cinematic

Scratchpad for docs/AVATARS_AND_EJECTION_PLAN.md. Ten original creature portraits chosen before entry, and a rose-petal dissolve that plays on every vote ejection. Everything below is the real markup, the real palette and the real keyframes — the app copies from here, it does not reinterpret it.

Nothing here reproduces Clair Obscur art, characters, names, terminology or audio. The creatures are drawn from scratch in this file. The effect is called petal dissolve in every shipped identifier.

1The ten creatures

Ten silhouettes that stay apart at 30 px. Every one is built from circles, ellipses, rectangles and short paths, in the same two-pixel ink line the paintress uses. No creature copies a named character from anything. AVATAR_BEETLE is the designated fallback for AVATAR_UNSPECIFIED and for any value the server does not know.

Why the art is code. The chip already renders inside a circular container at three sizes. Inline SVG scales to all of them from one source, reads the --av-* tokens, costs no request, and shows up in a diff. Ten PNGs would add ten fetches and freeze the palette.

Seats 2, 5 and 9 all picked the moth. The ring hue is derived from the player id, so the three still separate at a glance. Duplicate choices are allowed by the plan and are not discouraged in the picker.

3The join picker

Lives in web/src/ui/screens/home.ts, after the display-name field and before Create and Join. It is not reachable from the lobby or from a live match. One creature is already selected on load, so the existing name-then-Enter path still enters a room in one keystroke.

One face at a time rather than a grid of ten. At grid size the creatures were 46 px of mush, and the whole reason to draw them was that somebody looks at them. The cost is that reaching a specific face takes up to five presses — which is what the dots are for. Without a position readout a cycler feels endless and never tells you that you have now seen all of them.

4The gommage — five acts

Press a button. This is the real effect at the real speed. It reacts to the PlayerEliminated broadcast the room already sends, so it needs no new protocol event, no server-side timer and no new phase. The whole run is 7800 ms inside an eight-second PHASE_RESOLVING, and 5000 ms of that is the verdict holding at full opacity.

The anticipation is the pause, not the motion. Act 3 is nine hundred milliseconds in which almost nothing happens, and it is the reason the burst lands. The cut is sized by the VERDICT, though, not by the animation: the line has to be read, so it gets five whole seconds and everything before it was compressed to pay for that. The held beat was the one thing not compressed. Switch the tempo to Quick to see what the line looks like when it is not given the time.

This overruns the plan on purpose, and the verdict is why. AVATARS_AND_EJECTION_PLAN.md asks for 1.2–1.5 s. A line that fades in and straight back out inside that is a line nobody finishes reading. ResolveDuration is 8 s (internal/room/api.go:120) and the overlay opens at the top of it, so the real budget is 8000 ms and the cut spends 7800 of it. The remaining 200 ms of margin only ever has the closing fade in it — an overlay at near-zero opacity that never takes pointer events — so even a phase change arriving early costs nothing visible. The constraint that actually matters is that afterResolve is never delayed, and it is not: the cinematic reads the phase clock and never touches it.

Why 7.8 s and 36 petals still cannot cost a frame. 48 absolutely-positioned spans — 36 petals and 12 motes — animated on transform and opacity and promoted with will-change. No per-frame JavaScript, no canvas, no layout read, no networked particle. The controller writes each element's custom properties once at build time and then only adds and removes a class. A longer run and a bigger crowd are more compositor frames, not more main-thread work — and 48 promoted layers is well inside what a phone composites without dropping one, since they all appear and retire together.
One variable retimes everything. Every duration and delay is calc(n * var(--k)). The tempo switch above sets --k, and nothing else changes. If 7.8 s turns out to be too long in a real match, it is one number.
Where it lives. Mounted once beside the screen root from web/src/main.ts, never inside result.ts. Screens mount and unmount underneath it — over 7.8 s the result screen can be replaced by the final reveal while the petals are still falling, which is exactly why the overlay cannot belong to a screen.
It must fire exactly once. The controller keys on round : playerId : eliminated and only accepts a value that arrived on the live playerEliminated broadcast. A Snapshot, a resync, and the ERROR_CODE_KICKED reset all carry elimination state and must all be refused.
After it ends the overlay is emptied and hidden, so it cannot swallow a click on the screen beneath it or re-appear on a routine store update.

The wording is not rewritten for the cinematic. verdict() at web/src/ui/screens/result.ts:26 is extracted to a shared module and both callers read it, so Hidden mode cannot disclose an alignment through a second copy of the copy.

Reduced motion. Under prefers-reduced-motion the run is 7.5 s and nothing rises, drifts, spins or falls. The verdict still gets its full five seconds — a reader who cannot take fast motion is the last person who should be given less time to read. No petal and no mote is created at all. The room dims, the portrait cross-fades, and the same authorised line still arrives on its own later beat — the build-up survives as timing, which is not motion. The result is announced once through the existing aria-live="polite" region in the app chrome. Focus never moves.

6The cue

One quiet addition to web/src/audio/cues.ts, on the same C major pentatonic scale as everything else. It is the descending answer to resolve, an octave down and half the level. 

// web/src/audio/cues.ts
// The petal cue. Deliberately quiet: an ejection is already the
// loudest thing on screen, and this only has to land under it.
//
// The offsets are the whole trick. RESOLVING plays `resolve`
// (A5 -> E5, tail out at ~0.57 s) and PlayerEliminated lands in
// the very next frame. Acts 1 to 3 are therefore already spoken
// for, and this cue simply starts where they end. The synth's own
// audio clock spaces the notes, so no cue is dropped and no
// setTimeout is involved.
//
//   1.90 s  the petals leave      (act 4)
//   2.55 s  the verdict lands     (act 5)
ejection: {
  level: 0.32,
  notes: [
    { freq: C5, at: 1.90 },
    { freq: G4, at: 2.06, dur: 0.5 },
    { freq: E5, at: 2.55, dur: 0.6, gain: 0.7 },
  ],
},

11Out of scope

Uploaded avatars, account persistence, unlockable cosmetics, avatar exclusivity, and editing a choice from the lobby or mid-match. No change to any vote rule, ejection timing, phase timer, spectator permission, or the host kick. No reproduction of Clair Obscur art, characters, terminology or audio.
